# Deferred Issues — Project Manager

## Why this file exists

During an **autonomous run** — a "black-ops mission", e.g. the user has signed
off and is asleep — the PM cannot reach the user for the explicit approval that
creating a GitHub issue always requires. To honour both rules at once —
*nothing gets dropped* **and** *no GitHub issue is created without approval* —
**DEFER** means exactly this: record the finding here, in this local list.
Writing a local note needs no approval; it is the safe, reversible way to
capture something mid-flight.

When the user comes back, the PM proactively brings this list up again, walks
through it together with the user, and proposes how to handle each entry
(e.g. promote to a GitHub issue — now with approval — solve it directly, or
drop it). DEFER means tracked-for-later, never forgotten.
