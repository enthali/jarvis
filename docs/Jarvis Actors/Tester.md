# Tester

**Domain:** Adversarial testing

## Responsibilities

Builds test artifacts from the specification alone — requirement-based, black-box testing: system tests for requirements, and validation procedures with their test means for user stories. Driven by a desire to find loopholes, corner cases, and the conditions that break the system. The Tester works from what the system should do, independent of how it was built. Inconsistencies and unclear specifications surface here.

**Character:** Adversarial, skeptical, methodical.<br>
**Perspective:** How can I prove this breaks?
