## Goal

Split the monolithic `enthali.jarvis` extension into a kind-agnostic **session
engine** (core) plus optional **PIM** and **Recorder** add-ons, using an IoC
plugin registry (proven by the research spike). Core keeps id `enthali.jarvis`
so the monolith updates in place. A syspilot-only install shows provably zero
project/event surface — not in the tree, not in settings, nowhere.

## Release scope

v0.8.0 bundles, in one release:

- 3 already-merged CRs on develop (`remove-open-recording-icon`,
  `initprompt-extract-overflow`, `listprojects-shape-parity`)
- the full modularization (Phases A–C below)

## Locked decisions (2026-06-17)

- One v0.8.0 release (no intermediate v0.7.1).
- Monorepo (npm workspaces), one `docs/` spec tree, lockstep versioning.
- Per-CR feature branches off develop, squash-merged. develop stays releasable
  through Phases A–B (one extension, behaviour unchanged).
- Core keeps id `enthali.jarvis`. Tool namespacing `jarvis_*` / `jarvis_pim_*`
  / `jarvis_rec_*`. `JarvisCoreApi.version` present from day one.
- `context.md` is not an engine concern (session/agent owns it); tree factory is
  task-agnostic (PIM decorates its own kinds).
- Distribution channel (Marketplace / Open-VSX / private registry) deferred to a
  separate later CR — orthogonal to the split.

## CR chain

### Phase A — Engine contract

- **A1** Freeze `JarvisCoreApi` v1 (types per report §4, grounded in the spike's
  proven `SpikeEngineApi`); register `session` internally via `registerEntityKind`
  as the reference application; add `docs/design/spec_engine.rst`. No behaviour change.

### Phase B — Internal modular cut along future seams

*Still one extension. Behaviour unchanged. Each CR test-green before merge.*
Target layout: `src/{extension.ts (composition root), engine/, apps/session/,
apps/pim/, apps/recorder/, shared/}` — module boundaries already match the future
extension seams (no throwaway structure).

- **B1** Module skeleton: `shared/` (logging, templates, helpers) + `engine/`
  (scanner, configPaths, mcpServer, sessionLookup, messageQueue, heartbeat
  scheduling hook, registerTool).
- **B2** Extract `apps/recorder/` (most self-contained first); ride-along F6
  (file-watcher instead of 2-min polling). *needs B1*
- **B3** Generic tree-provider factory (F2): collapse the three tree providers
  into one `TreeProvider<K>` + per-kind config; factory stays task-agnostic. *needs B1*
- **B4** Unify create/find/open → engine `createEntity` (F5); create tools become
  kind-dispatch; `openEntity` absorbs the F3 settle delays + F4 init-prompt. *needs B3*
- **B5** Extract `apps/pim/` (pim + outlook + project/event apps + their
  tools/trees/settings); PIM decorates project/event kinds with tasks. *needs B3, B4*
- **B6** Extract `apps/session/`; reduce `extension.ts` to a ~150-line composition
  root. *needs B5*

### Phase C — Physical split + package manager

*Monorepo (npm workspaces). Emits 4 .vsix. Packaging changes here.*

- **C1** Monorepo scaffolding + `packages/core` (id `enthali.jarvis`); verify
  in-place update from the monolith id.
- **C2** `jarvis-pim` separate extension (own `contributes.views` + `configuration`,
  `extensionDependencies: ["enthali.jarvis"]`); prove zero-trace with core-only
  install. *needs C1*
- **C3** `jarvis-recorder` separate extension; verify install combos (§8.1a). *needs C1*
- **C4** Extension Pack `enthali.jarvis-suite` + 4-vsix build. *needs C2, C3*
- **C5** Self-updater → package manager (multi-member update, settings-seeded
  add-on offer, uninstall). *gate: R9 verified first* · *needs C1*

### Release
