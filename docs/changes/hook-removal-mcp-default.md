## Intent And Outcome

**Owner:** Project Manager<br>
**Status:** approved<br>
**Approval evidence:** The User released the Contract and its start in chat on 2026-11-02 ("ok ja starte den change bis morgen") after the text was presented; the two items come from his request of the same day.

### Goal

Two things become true:

1. Jarvis contains no hook functionality: nothing installs, provisions, listens for or depends on agent hooks, and no function remains that exists only because hook events arrive. Specification, code, settings, generated workspace files, tests and documentation agree.
2. The embedded MCP server starts only when the User has enabled it. The code follows the specified default `false` for `jarvis.mcp.enabled`.

### Value

Hooks failed in a clean Windows Sandbox without `node` and blocked every tool call of an Actor chat; with the hook functionality gone this failure cannot occur and Jarvis needs no `node`. For the MCP server, the product starts no local server without the User's consent, and code, specification and guides state the same default.

### Scope

All hook functionality in the specification, code, settings, generated files, tests and documentation, and the default of `jarvis.mcp.enabled` in code and guides. Functions that today exist only on hook events (for example the touched-files tracking, which consumes the hook engine) belong to the hook functionality; the Architect inventories them first and records what is removed with it. The migration of the default is visible to existing installations without an explicit setting: the MCP server no longer starts automatically for them, and the release notes say so.

### Observable Outcome

- A workspace that an earlier Jarvis version provisioned has no Jarvis-managed hook files after the upgrade, and an Actor chat there calls tools on a machine without `node`.
- A fresh Jarvis installation does not start the MCP server until `jarvis.mcp.enabled` is set to `true`; the server then starts.
- The specification, settings reference, guides and release notes contain no hook functionality and state the MCP default `false`.
