## Summary

The v0.11.1 CI failure revealed a process gap: when `esbuild` was added as a `devDependency` to the pim/recorder/mcp workspace packages, the root `package-lock.json` was not updated before release, causing `npm ci` to fail in CI. This change adds an Acceptance Criterion to `SPEC_REL_PKGCONTRACT` (and a corresponding requirement to `REQ_REL_PKGCONTRACT`) requiring that the root lock file is kept in sync whenever workspace package dependencies change, and that `npm ci` is verified to pass locally before any release tag is pushed.
