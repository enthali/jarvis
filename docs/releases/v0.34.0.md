## Objective And Scope

**Owner:** Project Manager<br>
**Status:** approved

### Objective

Release 0.34.0 makes Jarvis work where VS Code Server hosts the Agent Host, starting with GitHub Codespaces, and raises the VS Code minimum to 1.144.0. It also ships the `powershell` job step with its `pwsh`-to-`powershell` fallback, the product-wide acceptance model with its pre-integration Needs check, and the platform facts in the documentation. The version number is Release's SemVer decision; the Project Manager's candidate is 0.34.0, because the release contains a feature and a raised minimum VS Code version.

### Included Changes

1. `vscode-minimum-1-144` — integrated at `3d9a40c2`; closed at `05cbbca4`. The VS Code minimum is `^1.144.0`.
2. `uat-status-model-cleanup` — integrated at `6e8352c0`; closed at `c6020f3b`. Product root and modules, 38 acceptance journeys, and the Needs check before integration.
3. `ahp-codespaces-discovery` — integrated at `9925bd60`; closed at `c9814643`. Agent Host discovery in a Codespace (fallback user data folder, `standalone` hosts, `tcp` endpoints) and drive-letter normalisation of the folder key on every platform.
4. `platform-neutrality-audit` — integrated at `77ccddd8`; closed at `501af635`. The `powershell` job step falls back from `pwsh` to `powershell` with a clear error; platform facts in the documentation.

Also on `development` since `v0.33.0`, without a Change Contract: Admin's `767f4909` (contract-statistics skill and closure checklists) and three documentation commits (`6df5fa04`, `cce0286e`, `2771fb03`). Release decides whether each belongs in the release notes.

### Known Limitations

- Windows live connection of the Agent Host discovery is verified in the Windows Sandbox (2026-11-19). macOS is not verified; the User has no Mac. WSL and SSH are not verified.
- In a Codespace, discovery, sending from an Actor chat and opening Actor chats are verified (User, 2026-11-19); Dev Tunnels and the Agents window connected to a Codespace are outside that validation.
- The live run of `ac_heartbeat.rst` with `pwsh` or `powershell` is not executed; the step is covered by Linux system tests with an injected spawner.
- The acceptance journeys other than the Actor Phase-1 scenarios are `approved` and not executed.
