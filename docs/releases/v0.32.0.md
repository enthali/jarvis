## Objective And Scope

**Owner:** Project Manager<br>
**Status:** approved<br>
**Approval evidence:** The User reviewed the objective and the known limitations in chat on 2026-11-03, corrected several of them (two windows, roadmap wording, Agents window, tree and status bar features) and set Release start ("release start").

### Objective

Publish the release in which Jarvis runs entirely on VS Code's Agent Host: Actors exchange messages and open their chats through it, and they can be used in the editor and in the Agents window, where several Actor chats can be open side by side. Nothing of the old chat UI path remains. The release also removes all hook functionality and starts the embedded MCP server only when the User has enabled it. Release confirms the version under its Version artifact; the Project Manager proposes `0.32.0` because the release contains breaking changes.

### Included Changes

1. `ahp-mvp` - Actor messages and Actor chats through the Agent Host Protocol, with changed message tools, the activity state taken from the Agent Host and the Windows Sandbox test environment; squash-integrated at `93463aa`; Change Contract closed.
2. `hook-removal-mcp-default` - all hook functionality and the touched-files function removed without replacement, cleanup of the five legacy hook files on activation, MCP default `false`, and a `repository` field for the PIM, Recorder and MCP packages; squash-integrated at `685627e`; Change Contract closed.

### Known Limitations

- Jarvis needs an available, authenticated VS Code Agent Host; there is no fallback to the old chat UI. It was developed and checked on VS Code 1.143.1 and 1.144.0.
- Jarvis serves the Agent Host of its own window. A remote window (WSL, SSH, Dev Tunnels) is not served. The same workspace open in two windows is not tested and probably does not work.
- Chats that Jarvis creates show in the Agents window only after **Created In > jarvis-core** is ticked in the session filter.
- Projects must update their own instructions, skills and agents to the changed message tools; the old tool inputs `senderSession` and `destination` are gone.
- The Recently Touched Files function is removed in this release; it is on the roadmap for a future version. The leftover folder `.jarvis/state/touched-files/` and an old `chat.hookFilesLocations` entry in a workspace's `.vscode/settings.json` stay on disk.
- The embedded MCP server no longer starts without an explicit `jarvis.mcp.enabled` of `true`, also for installations that never set it.
- Not run in the validation of the included changes: the manual Agent Host scenarios and the upgrade of a workspace that still holds old hook files (`US_UAT_MSG` T-22).
- Agents window: the User observed on 2026-11-03 in the Sandbox that Actor chats and the Kanban board work there. Flow, the message view and log, cannot be opened from the Agents window yet. Everything that Jarvis offers through the status bar or a tree does not work there: the activity and mail markers in the ACTORS tree, the PIM mail notification in the tree, and the Recorder, which has no UI that can be triggered from the Agents window. A solution for these is on the roadmap; there is no plan for it yet. Syspilot was not checked there.
